# Choosing scope and foundations

A prerequisite belongs NOW only if its absence blocks the next outcome or makes
the learner's result materially unreliable. For example, running a stateless API
locally does not require orchestration; persisting user data changes that scope.

| Evidence | Path adjustment |
| --- | --- |
| Learner can explain and apply a concept | Skip its lesson; revisit only if a later attempt reveals a gap. |
| Learner reports familiarity | Start there; one practical check is enough when consequential. |
| Learner has never programmed and wants broad ML competence | Clarify purpose; include programming, data and mathematical foundations as needed. Prefer a sequenced curriculum over a tiny project checklist. |
| Learner wants fundamentals-first | Put the relevant model and worked reasoning before the application; use a bounded foundation block. |
| Repeated failures share one prerequisite | Pause the build and teach that prerequisite, then retry. |
| Deadline cannot accommodate prerequisites | Reduce the deliverable or extend the schedule; do not relabel exposure as competence. |
| Exam, credential, broad professional competence | Prefer a syllabus with coverage and cumulative assessment. |
| Long-term retention or theory is the goal | Include spaced retrieval, varied practice and deeper study, not just a one-off build. |

Recommend resources by fit: prerequisites, coverage, exercises, feedback, duration,
cost and learner preferences. Verify current availability before naming a specific
course. With no browsing, describe selection criteria or use learner-supplied
resources instead of inventing recommendations.

End a session with a tiny checkpoint: demonstrated ability, unresolved gap,
deferred topics with revisit conditions, and next action. Offer it in chat;
writing it to disk or assuming cross-session memory is not required.
